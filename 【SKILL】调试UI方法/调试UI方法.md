# Python GUI 调试通用指南

## 核心原则

GUI 调试与普通代码调试不同：**布局问题往往无法通过断点发现，必须通过几何数据（位置、尺寸、可见性）、视觉检查和时序分析来定位**。不同框架 API 不同，但调试思路通用。

> 平台特定 API 和代码示例见 [references/](./references/) 目录。

---

## 一、调试脚本模板

### 1. 最小化复现脚本

隔离问题到最小组件，不依赖完整应用启动。

**通用模式**：
1. `sys.path.insert(0, ...)` 确保能导入项目包
2. 创建最小父窗口（不需要启动 MainWindow）
3. 直接构造目标组件
4. 用延迟回调在 layout 稳定后检查状态
5. 用非模态 show + 事件循环，方便定时器控制

### 2. 交互式调试窗口

需要手动触发多种场景时，构建带按钮和日志区域的调试窗口。

**通用模式**：
1. 创建主窗口，添加操作按钮（打开对话框、模拟 resize、触发事件等）
2. 持有被调试组件的引用
3. 在操作前后 dump 状态
4. 用延迟回调在 layout 稳定后再次 dump

### 3. 全应用启动脚本

需要完整上下文（服务、数据、导航）时，启动完整应用后操作特定页面。

**通用模式**：
1. 创建 MainWindow
2. 显示并强制处理待处理事件
3. 操作特定页面/组件
4. 再次强制处理事件

## 二、通用调试方法

### 2.1 几何数据 Dump

打印组件的 pos/size/visible 是定位布局问题的第一步。

**需要获取的信息**：
- 位置 (x, y)、尺寸 (width × height)
- 可见性 (visible/viewable/shown)
- 最小/最大尺寸约束
- 推荐尺寸 (sizeHint / best size)

**检查项**：
- widget 是否超出父容器边界（`x + width > parent.width`）
- 居中是否正确（`(parent.width - widget.width) // 2 == widget.x`）
- 分隔线是否在两个面板之间（`sep.x >= left.right && sep.right <= right.x`）
- 最小/最大尺寸约束是否生效
- 推荐尺寸是否合理

### 2.2 时序分析

GUI 的 layout 是异步的，`show()`、`resize()` 后 layout 不会立刻完成。用定时器在不同时间点 dump 状态。

**三个关键时间点**：
- **idle/0** — 在当前事件循环迭代完成后执行，layout 通常已 activate
- **100ms** — 足够等待大部分 layout 计算
- **500ms** — 等待淡入动画完成

**核心思路**：在 show/resize 后，于不同延迟点 dump 几何数据，观察 layout 何时稳定。

### 2.3 事件流追踪

当不确定哪个事件导致了状态变化时，monkey-patch 关键方法加日志。

**通用模式**：
1. 保存原始方法引用
2. 替换为带日志的包装函数
3. 在调用前后打印关键状态
4. 可选：打印调用栈 `traceback.print_stack(limit=5)`

**可追踪的事件类型**：
- resize / configure / size 事件
- show / map / expose 事件
- layout request 事件
- eventFilter / 事件分发

### 2.4 截屏保存

视觉问题用截屏辅助分析。保存为 PNG 文件后可反复对比。

### 2.5 强制 Layout 重算

有时需要手动触发 layout 重新计算。

**通用模式**：
1. 使 layout 失效（invalidate）
2. 激活 layout（activate）
3. 递归处理子组件
4. 强制处理待处理事件

### 2.6 样式与主题调试

检查实际生效的样式值，而非只看代码中设置的值。样式可能被父组件、主题、QSS/样式表覆盖。

**通用思路**：
1. 读取运行时实际样式值（背景色、字体、边距等）
2. 与代码中设置的值对比
3. 检查是否有多个样式源冲突

### 2.7 辅助色块定位法

在不确定组件实际占据的区域时，给组件加半透明背景色来可视化边界。

**技巧**：
- 给相邻组件用不同颜色，快速发现重叠、间隙、对齐问题
- 用半透明色（如 rgba(255,0,0,0.3)）避免遮挡内容
- 红色 = 问题组件，绿色 = 参考组件，蓝色 = 容器边界

### 2.8 组件树 Dump

打印完整的组件层级和属性，定位"看不到"的组件。

**需要输出的信息**：
- 类名、尺寸、位置
- 可见性
- 层级缩进表示父子关系

**常见发现**：
- 组件在树中但 visible=False
- 组件尺寸为 0×0
- 组件位置在父容器之外
- 组件层级嵌套错误（挂在错误的父节点下）

### 2.9 焦点与输入调试

输入框无法输入、快捷键不响应等问题。

**排查方向**：
1. 查看当前焦点在哪个组件
2. 检查组件的焦点策略（是否可接受焦点）
3. 追踪焦点变化事件
4. 检查事件是否被 eventFilter / bind 拦截

### 2.10 信号/回调追踪

不确定哪些回调被触发、参数是什么时。

**通用模式**：
1. 保存原始回调引用
2. 替换为带日志的包装函数
3. 打印参数和调用栈
4. 可选：打印返回值

**对于变量绑定**：追踪变量的读写变化。

### 2.11 性能分析

UI 卡顿、渲染慢时。

**通用方法**：
- **cProfile** — 全局性能分析，找热点函数
- **渲染计时** — 在绘制回调中计时，超过 16ms（60fps 一帧）则报警
- **事件风暴检测** — 统计单位时间内事件触发次数，超过阈值则报警

### 2.12 辅助工具

| 工具 | 用途 | 适用框架 |
|------|------|----------|
| **GammaRay** | 对象树浏览、属性实时编辑、信号追踪 | PyQt/PySide |
| **Qt Inspector** (Qt Creator) | 运行时检查组件层级和属性 | PyQt/PySide |
| **Spyder** | IDE 内置对象检查器 | PyQt/PySide |
| **Inspect.exe** (Windows SDK) | Windows 原生 UI 自动化检查 | wxPython/Win32 |
| **Accessibility Inspector** (macOS) | 无障碍树检查，可查看所有 UI 元素 | 所有 |
| **DevTools** (CEF/Electron) | Web 渲染 UI 的 DOM 检查 | Web-based |
| **pyautogui + PIL** | 自动化截屏对比 | 所有 |
| **pytest-qt** | 组件的自动化测试 | PyQt/PySide |
| **page-object 模式** | 将 UI 元素抽象为可测试对象 | 所有 |

## 三、常见陷阱与经验

### 1. Layout 会覆盖手动 resize

布局管理器 activate 时会将组件收缩至推荐尺寸，覆盖手动设置的位置和大小。

**解决方案**：从布局管理器中移除组件，手动控制位置和尺寸；或使用固定尺寸标志。

### 2. maximumSize 阻止窗口扩大

设置最大尺寸会阻止窗口在父窗口变大时跟随扩大。

**解决方案**：只限制内部组件的最大尺寸，不限制容器窗口本身。

### 3. resize 回调中使用旧的目标尺寸

父窗口 resize 时同步调用子窗口 resize，触发回调。此时如果目标尺寸还是旧值，子组件会被放到错误位置。

**解决方案**：在 resize 回调中同步更新目标尺寸。

### 4. minimumWidth 过大导致布局重叠

水平布局在空间不足时会重叠子组件，而不是截断。

**解决方案**：确保所有子组件的最小宽度之和不超过可用空间；允许收缩。

### 5. 延迟回调时序问题

idle/0 延迟回调不够早也不够晚：
- 不够早：layout 还没 activate，拿到的尺寸是旧的
- 不够晚：后续事件会覆盖你的设置

**解决方案**：在 resize 回调中同步处理，不依赖延迟回调。

### 6. geometry 设置与读取不同步

设置尺寸后，读取方法不会立即返回新值。

**解决方案**：强制处理待处理事件后再读取。

### 7. 批量更新闪烁

批量更新 UI 时频繁重绘导致闪烁。

**解决方案**：用冻结/解冻机制包裹批量操作。

### 8. schedule_once(0) 不是立即执行

延迟 0 的回调在下一帧执行，不是立即。

**解决方案**：需要立即执行时直接调用函数。

### 9. 跨平台 DPI 缩放

高 DPI 显示器上，逻辑像素与物理像素不同。

**解决方案**：启用 DPI 感知；调试时打印缩放比确认。

### 10. 事件循环嵌套与模态对话框

模态对话框会启动嵌套事件循环，可能导致意外的回调执行顺序。

**解决方案**：避免在模态对话框打开期间通过定时器/回调修改父窗口状态。

## 四、调试流程清单

遇到 UI 问题时，按以下顺序排查：

1. **复现** — 写最小化复现脚本，确认问题可独立复现
2. **几何 dump** — 打印所有相关组件的 pos/size/visible
3. **色块定位** — 给可疑组件加半透明背景色，可视化实际区域
4. **时序分析** — 在不同时间点 dump 状态，确认 layout 何时稳定
5. **事件追踪** — monkey-patch resize/show/layout 回调，打印调用栈
6. **组件树 dump** — 打印完整层级，确认组件是否真的在树中
7. **样式检查** — 打印实际生效的样式值，确认是否被覆盖
8. **截屏对比** — 保存截图辅助视觉分析
9. **性能分析** — 卡顿时用 cProfile 或绘制计时
10. **工具辅助** — 使用 GammaRay / Accessibility Inspector 等运行时检查工具
