# 架构规范

## 1. 项目概述

AI 池是一个基于 CLI 命令行的 AI 资源池管理系统，支持多 API Key、多模型的统一管理与智能路由。用户可将多个 AI 服务商（支持 OpenAI、Azure、Anthropic、Hugging Face 四种格式）的 Key 和模型组织为“AI 池”，实现故障转移、速率限制、并发控制、熔断重试等能力；也可创建独立的“普通 AI”（SingleAI）直接使用。

---

## 2. 整体架构

采用**分层架构**，自上而下分为三层：

```
┌──────────────────────────────────────────────┐
│              CLI 交互层 (REPL)                │
│  repl          主 REPL 类，状态管理与模式切换 │
│  lang_cmds     /language 语言切换命令         │
│  direct_cmds   连接/切换/模型命令             │
│  pool_cmds     池/AI 管理命令                 │
│  chat_cmds     对话管理命令                   │
│  sender        消息发送（路由/直连/单AI）     │
│  pool_editor   池/单AI 编辑器（子命令模式）   │
│  printer       输出格式化与路由状态展示       │
├──────────────────────────────────────────────┤
│              核心业务层                       │
│  models/            数据模型（dataclass）     │
│  pool/              池管理/路由/限速/测试     │
│  client/            API 调用（流式对话）      │
│  settings/          设置持久化                │
│  i18n/              国际化支持                │
│  log/               日志系统                  │
├──────────────────────────────────────────────┤
│              数据持久层                       │
│  (data/pools.json, data/settings.json)       │
│  (data/locales/*.json)                       │
└──────────────────────────────────────────────┘
```

### 2.1 分层职责

| 层次 | 职责 | 关键约束 |
|------|------|----------|
| **CLI 交互层** | 用户交互、命令解析、状态展示 | 不直接调用网络 I/O |
| **核心业务层** | 数据模型、路由算法、速率限制、API 调用 | 纯逻辑，不依赖 CLI 层 |
| **数据持久层** | JSON 文件读写、配置持久化 | 文件操作需要错误保护 |

### 2.2 依赖方向

- CLI 交互层 → 核心业务层 → 数据持久层
- **严禁反向依赖**（core 层不可 import cli 层）

## 4. 数据模型

数据模型全部定义在 `src/core/models.py`，使用 `dataclass` 实现。

### 4.1 模型关系

```
AIPool (name: str)                    # AI 池，name 即唯一 ID
  └── keys: list[ApiKeyConfig]
        ├── base_url: str
        ├── api_key: str
        ├── type: str                          # openai|azure|anthropic|huggingface
        ├── label: str                         # 供应商名称（显示用）
        ├── errors: ErrorConfig
        │     ├── max_concurrency: int         # 默认 1
        │     ├── timeout: int                 # 默认 30s
        │     ├── max_errors: int              # 默认 3
        │     └── failure_pause: int           # 默认 40s
        ├── rate_limits: Optional[list[LimitRule]]
        └── models: dict[str, ModelOverride]
              ├── model_id: str
              ├── rate_limits: list[LimitRule]
              └── (其他可选覆盖字段...)

SingleAI (name: str, alias: str)      # 普通 AI，alias 可选别名
  ├── key: ApiKeyConfig               # 单个 Key（不含 models 字段）
  └── models: list[str]               # 模型 ID 列表

LimitRule:
  - type: "time_per_req" | "count_per_time" | "tokens_per_time"
  - time: int
  - count: Optional[int]
  - tokens: Optional[int]
```

### 4.2 双类型配置规范

| 类型 | 标识方式 | 说明 |
|------|----------|------|
| `AIPool` | `name` 即 ID | 多 Key 路由，支持故障转移、熔断 |
| `SingleAI` | `alias` 可选别名 | 单 Key 直连，超时固定 30s，无 errors/rate_limits 字段 |

### 4.3 配置继承与覆盖规则（仅 AIPool）

- `ModelOverride` 中的 `None` 字段表示**继承** `ApiKeyConfig` 的同名字段值
- 限制取**两者最大值**（保守策略），而非简单继承

## 5. 核心模块设计

### 5.1 池管理器 (`pool_manager.py`)

**类：`PoolManager`**

- 全局单例模式（模块级 `pool_manager` 实例）
- 管理 `AIPool` 和 `SingleAI` 两种条目
- 支持 CRUD 操作：`add_entry` / `remove_entry` / `rename_entry` / `update_entry`
- 别名解析：`resolve_model(query)` 三级匹配（条目名 > single alias > 模型 ID 原文）
- JSON 持久化：`load()` / `_save()`

### 5.2 路由器 (`router.py`)

**类：`PoolRouter`**

核心路由引擎，实现选择、熔断、冷却、并发控制（仅用于 AIPool）。

#### 5.2.1 状态追踪

每个 `(key_idx, model_id)` 称为一个 entry，追踪以下状态：

| 状态 | 类型 | 说明 |
|------|------|------|
| `_key_conc[ki]` | int | Key 级别当前并发数 |
| `_mdl_conc[(ki, mid)]` | int | 模型级别当前并发数 |
| `_key_errors[ki]` | int | Key 级别连续错误计数 |
| `_mdl_errors[(ki, mid)]` | int | 模型级别连续错误计数 |
| `_key_reqs[ki]` | int | Key 级别累计请求计数 |
| `_mdl_reqs[(ki, mid)]` | int | 模型级别累计请求计数 |
| `_key_cooldown[ki]` | float | Key 冷却到期时间戳 |
| `_mdl_cooldown[(ki, mid)]` | float | 模型冷却到期时间戳 |

#### 5.2.2 选择算法 (`select_entry`)

1. 遍历所有 entry，调用 `_entry_available()` 检查可用性
2. 可用 entry 加入候选列表；暂时不可用的记录最短等待时间
3. 候选列表非空 → 随机选择一个 → 调用 `_reserve()` 预留资源 → 返回
4. 候选列表为空 & 有暂时不可用的 entry → 等待 `min(max(min_wait, 0.5), 5.0)` 秒后重试
5. 所有 entry 永久禁用 → 返回 `None`

#### 5.2.3 熔断机制

- 错误计数超过 `max_errors` → 永久禁用（本会话内）
- 请求计数超过 `max_requests` → 永久禁用（本会话内）
- 错误发生后进入冷却期（`failure_pause` 秒），冷却期内返回 `wait > 0`
- 会话重置（`reset_session()`）清空所有计数和冷却状态

### 5.3 速率限制器 (`rate_limiter.py`)

**类：`RateLimiter`**

滑动窗口实现，线程安全。

| 模式 | 行为 |
|------|------|
| `time_per_req` | 窗口内只能请求 1 次，间隔至少 N 秒 |
| `count_per_time` | 窗口内最多请求 N 次 |
| `tokens_per_time` | 窗口内最多消耗 N 个 token |

### 5.4 API 客户端 (`api_client.py`)

- 使用标准库 `urllib` 实现，无第三方依赖
- 四个公开函数：
  - `fetch_models()`：获取模型列表
  - `fetch_model_detail()`：获取单个模型详情
  - `test_connection()`：测试连接可用性
  - `stream_chat()`：流式对话调用
- SSL 验证当前为 `CERT_NONE`

## 6. CLI 交互层架构

### 6.1 REPL 模式设计

基于 MRO 多继承实现，`REPL` 通过多继承组合五个功能类：

| 类 | 职责 |
|------|------|
| `LanguageCommands` | 语言切换命令：`/language` |
| `DirectCommands` | 连接命令：`/connect` |
| `PoolCommands` | 切换/管理命令：`/model`, `/models`, `/status`, `/pool` |
| `ChatCommands` | 对话命令：`/new`, `/clear`, `/export`, `/params` |
| `Sender` | 消息发送：路由模式 / 直连模式 / 单AI模式 |

### 6.2 双模式状态机

REPL 有两种运行模式，由 `self.mode` 控制：

| 模式 | `self.mode` | 说明 |
|------|-------------|------|
| 池路由模式 | `"pool"` | 通过 `PoolRouter` 自动选择 Key+Model，支持熔断转移 |
| 单AI模式 | `"single"` | 直连指定 Key，使用选定模型 |
| 池直连模式 | `"pool"` + `selected_pool_key` | 绕过路由，直连池内指定 Key |

### 6.3 Prompt 格式

| 模式 | Prompt | 示例 |
|------|--------|------|
| 池路由 | `[池名称]` | `[AI] > ` |
| 池直连 | `[池名称:供应商 模型]` | `[AI:智谱AI GLM-4.5-Flash] > ` |
| 单AI | `[供应商 模型]` | `[DeepSeek deepseek-v4-pro] > ` |

### 6.4 模型选择语法

| 语法 | 说明 |
|------|------|
| `/model <name\|alias>` | 切换到条目（自动选首个模型） |
| `/model <entry>:<model>` | 切换 single AI 并指定模型 |
| `/model <池>:<key序号或标签>:<model>` | 直连池内指定 Key（绕过路由，提示限速） |

## 7. 数据流设计

### 7.1 单AI对话

```
用户输入 → _send_via_single()
  → 限速检查（如有 rate_limits，等待）
  → stream_chat(kc.base_url, kc.api_key, model, ...)
  → 成功 → 记录限速 → 保存到 messages
  → 异常 → 打印错误
```

### 7.2 AI 池对话（路由模式）

```
用户输入 → _send_via_pool()
  → router.select_entry() → 阻塞直到有可用 entry
  → 获取 (ki, mid, kc, mo)
  → stream_chat(kc.base_url, kc.api_key, mid, ...)
  → 成功 → report_success() → 释放并发 → 保存消息
  → 异常 → report_error() → 冷却期 → 重试（最多 max_retries 次）
```

### 7.3 AI 池直连模式

```
用户 /model AI:1:GLM-4-Flash → selected_pool_key = 0
用户输入 → _send_direct_key()
  → 直接使用 pool.keys[ki] 发送（不走 router，不应用限速）
  → 切换时警告用户：直连模式不走限速，并打印 Key/模型限速策略
```

## 8. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 交互方式 | 自定义 REPL（MRO 多继承） | 轻量，无需 GUI 依赖，适合服务器/SSH 环境 |
| API 调用 | urllib | 无需安装 requests，标准库即可 |
| 数据模型 | dataclass | 简洁、不可变友好、序列化方便 |
| 持久化格式 | JSON | 人类可读、易于手动编辑 |
| 路由算法 | 随机选择 + 熔断 | 简单可靠，无需权重 |
| 状态管理 | 内存 + 锁 | 轻量，无需外部存储 |
| 条目 ID | AIPool 用 name，SingleAI 支持 alias | 池名唯一足够，单AI 需短别名方便切换 |
| 国际化 | 自定义 i18n 模块 + JSON 翻译字典 | 无第三方依赖，懒加载，8 种语言支持 |

## 9. 可扩展性设计

- **新增限制规则**：在 `LimitRule` 中添加 `type` 枚举值，在 `RateLimiter.check()` 中添加对应分支
- **新增路由策略**：修改 `PoolRouter.select_entry()` 中的选择逻辑（当前为随机，可改为轮询、最低负载等）
- **新增 CLI 命令**：在对应的 `*_cmds.py` 中添加 `do_xxx` 方法，更新 `help_text.py`，补充翻译键到 `data/locales/*.json`
- **多协议支持**：在 `api_client.py` 中新增函数，通过策略模式或工厂选择调用方式
- **新增语言**：在 `data/locales/` 中添加对应语言的 JSON 翻译字典，在 `I18nManager.SUPPORTED_LOCALES` 中注册

---

## 10. 约束与限制

- 支持四种 API 格式：`openai`、`azure`、`anthropic`、`huggingface`（通过 `api_type` 字段指定）
- 持久化为单文件 JSON，不适用于大规模并发写场景
- 速率限制为进程内内存实现，多进程部署需外部存储（Redis）
- SSL 验证已关闭，生产环境需通过配置开启
- 所有状态随进程销毁，重启后会话状态重置（配置数据保留）
