# 编码规范

## 1. 命名规范

### 1.1 Python 代码

| 类别 | 规范 | 示例 |
|------|------|------|
| 模块/包 | 全小写、下划线分隔 | `pool_manager`, `api_client` |
| 类 | 大驼峰 (PascalCase) | `PoolRouter`, `RateLimiter` |
| 函数/方法 | 全小写、下划线分隔 | `select_entry()`, `report_success()` |
| 变量 | 全小写、下划线分隔 | `pool_name`, `max_retries` |
| 常量 | 全大写、下划线分隔 | `POOLS_FILE`, `_DATA_DIR` |
| 私有属性/方法 | 前导单下划线 | `_lock`, `_save()`, `_log()` |
| 强私有 | 前导双下划线（少用） | `__instance` |
| 类型变量 | 全大写短名 | `T`, `K`, `V` |

### 1.2 文件与目录

- `src/`：源代码主目录
- `src/core/`：核心业务逻辑模块
- `src/core/i18n/`：国际化模块（翻译、语言检测）
- `src/cli/`：CLI 交互层（repl、pool_editor、printer）
- `data/`：运行时数据与持久化文件
- `data/locales/`：翻译字典（JSON 格式，每语言一个文件）
- `docs/`：项目文档
- 不要使用连字符 `-`，统一使用下划线 `_` 分隔
- `main.py` 作为项目根入口

### 1.3 禁止行为

- 禁止使用拼音、单字母命名（循环变量 `i`, `j`, `k` 除外）
- 禁止缩写不明确的名称（如 `mgr` 而非 `manager`，除非是局部短作用域）
- 禁止命名中混用中英文

## 2. 注释规范

### 2.1 总体要求

- **中文注释**，Doxygen 风格
- 模块/包必须在文件头添加模块说明 docstring
- 公开类、公开方法必须有 docstring
- 复杂逻辑块必须添加行内注释说明意图

### 2.2 Doxygen 风格

```python
"""模块/类/函数简短说明

可选详细说明，段落之间空行分隔。

Args:
    param1: 参数1的说明
    param2: 参数2的说明

Returns:
    返回值的说明

Raises:
    ValueError: 触发异常的说明
"""
```

### 2.3 注释内容要求

- 说明 **为什么这样做**，而非 **做了什么**（代码自身应能说明做了什么）
- 涉及算法、策略、边界条件时必须有注释
- TODO 注释格式：`# TODO(username): 需要做的事`
- FIXME 注释格式：`# FIXME: 需要修复的问题`
- 禁止在注释中标注旧版本信息、旧代码片段（直接删除）

## 3. 代码风格

### 3.1 PEP 8 基础

- 缩进：4 空格，禁止 Tab
- 行宽：不超过 120 字符
- 文件末尾保留一个空行
- 导入顺序：标准库 → 第三方库 → 本地模块（每组间空行分隔）
- 类的两个方法之间空 1 行，类与类之间空 2 行

### 3.2 导入规范

```python
from __future__ import annotations  # 必须在文件顶部的第一句

import json
import os
import threading
from collections import defaultdict
from typing import Optional, Callable

from core.models import AIPool, ApiKeyConfig
from core.rate_limiter import RateLimiter
```

- 禁止使用 `from module import *`
- 鼓励使用相对导入引用模块内成员（如 `from .models import ...`），但根模块可使用绝对导入

### 3.3 数据类型标注

- 所有函数必须标注参数和返回类型
- 使用 `Optional` 而非默认 `None` 时不标注
- 对复杂嵌套类型，使用类型别名

```python
def select_entry() -> Optional[tuple[int, str, ApiKeyConfig, ModelOverride]]:
```

### 3.4 字符串

- 非必要禁用 Unicode 字符和 Emoji
- 用户可见文本必须通过 `t()` 函数获取，禁止硬编码中文
- 日志文本也必须通过 `t()` 函数获取
- 命令关键字（`/model`、`/pool` 等）不翻译
- 翻译键命名规范：`模块.子模块.描述`，全小写，单词间用下划线连接
- 占位符使用 Python 标准 `{variable}` 格式，与 `str.format_map()` 兼容

```python
# 正确：使用 t() 函数
from core.i18n import t
error(t("model.error.pool_not_found", pool_name=pool_name))

# 禁止：硬编码中文
error(f"池 [{pool_name}] 不存在")
```

### 3.5 控制结构

- 避免多层嵌套（超过 3 层需重构）
- 条件判断优先处理早返回（early return）
- 使用 `with` 语句管理资源和锁

```python
# 正确：早返回
if not base_url or not api_key:
    return
# 业务逻辑...

# 正确：with 管理锁
with self._lock:
    self._key_conc[ki] += 1
```

### 3.6 防御性编程

- 对用户输入、API 返回值做合法性校验
- JSON 解析使用 `try/except` 包裹
- 对 `dict.get()` 提供默认值
- 整数/浮点转换使用 `try/except ValueError`

## 4. 模块化设计原则

- 每个模块职责单一，文件名即模块职责
- `core/` 模块不应直接依赖 `cli/` 模块，通过回调函数解耦
- 数据模型统一在 `models.py` 中定义
- 全局单例在模块级别创建（如 `pool_manager.py` 中的 `pool_manager`）
- 通过 `on_log` / `on_change` 回调机制实现 CLI 与业务层的松耦合

---

## 5. 日志规范

- 使用 `logging` 标准库（通过 `get_logger()` 获取模块级日志器）
- 日志文本必须通过 `t()` 函数获取，支持多语言
- 日志前缀格式：

| 类别 | 格式 | 示例 |
|------|------|------|
| 池路由 | `[池] ...` | `[池] 模型 [xxx] 请求失败，暂停 40s` |
| 路由选择 | `[路由] ...` | `[路由] label / model_id` |
| 错误 | `[错误] ...` | `[错误] label/model: 错误信息 (重试 2/10)` |
| 池信息 | `[PoolManager] ...` | `[PoolManager] 保存失败: ...` |
| i18n | `[I18nManager] ...` | `[I18nManager] 翻译键缺失: xxx` |

- 日志必须包含足够的上下文信息，便于问题定位
- 避免日志过度冗余，避免在热循环路径中打印日志
- 用户可见日志通过 `on_log` 回调传递，由 CLI 层渲染

---

## 6. 错误处理规范

- 异常捕获需精确，避免裸 `except:` / `except Exception:`
- 在临界区（锁、文件操作、网络请求）必须使用 `try/finally` 或 `with`
- 用户操作类异常向 CLI 层抛出，通过 `error()` 函数打印展示
- 网络请求类异常在调用处包裹为业务异常（中文描述）
- 回调执行必须加 `try/except` 保护，防止回调异常中断主流程

```python
def _notify_change(self):
    for cb in self._on_change_callbacks:
        try:
            cb()
        except Exception:
            pass  # 避免回调异常影响主流程
```

---

## 7. 线程安全

- 所有共享状态读写必须加锁（`threading.Lock`）
- CLI 操作在主线程执行，流式输出使用 `stop_check` 回调实现中断
- 使用 `daemon=True` 创建后台线程
- `stop_check` 回调是线程安全的取消机制

---

## 8. 安全规范

- API Key 不在日志中明文输出（UI 输入框使用 `show="*"`）
- SSL 验证在生产环境不应关闭（当前 `CERT_NONE` 因测试需要，后续应提供配置项）
- JSON 持久化文件不存储敏感信息外的额外数据
- 注入防御：所有用户输入在传入 API 之前不做拼接，使用结构化 JSON
